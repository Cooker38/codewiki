### 分层职责

| 层 | 职责 | 技术 |
|---|---|---|
| 接入层 | CLI 命令 + MCP stdio 服务 | typer + FastMCP |
| 图谱引擎 | Tree-sitter 提取 → 两阶段落库 SQLite → 图查询 API | py-tree-sitter + sqlite3 |
| Wiki 管线 | LLM 生成/更新 6 类文档 + AGENTS.md 注入 | langgraph + openai SDK |

| 产物层 | `.codewiki/codewiki.db` + `wiki/` + AGENTS.md | 文件系统 |

## 二、数据流

### 2.1 全量构建（codewiki init）

```
锁定分支（git rev-parse HEAD）
  → Tree-sitter 全量扫描
  → 两阶段落库 SQLite
     ├─ AST 阶段：contains + 文件内 references + unresolved_refs
     └─ ReferenceResolver：跨文件绑定 calls/imports/extends/…
  → 图谱就绪
  → langgraph 管线：
     ① 规划文档结构（哪些符号→哪些页面→哪些目录）
     ② 分组组 prompt（并行 fan-out per 页面）
     ③ 调 LLM 生成 wiki/*.md + 注入锚点
     ④ 生成 wiki/quickstart.md 索引 + AGENTS.md 注入
     ⑤ 后处理（一致性校验、锚点交叉验证）
  → 记录 last_indexed_commit
```

### 2.2 增量同步（auto_sync 或 codewiki sync）

```
轮询 git rev-parse <branch>
  → 与 last_indexed_commit 比对
  → 不一致 → git diff --name-status C_old C_new
  → 删除文件：级联删节点+边 + 跨文件边复活
  → 新增/修改文件：重提取 + storeExtractionResult
  → 定向重绑 unresolved_refs
  → 从变更符号集合反查受影响 Wiki 段落
  → langgraph 管线（缩小范围，只重写受影响页）
  → 更新 last_indexed_commit = C_new
```

### 2.3 查询（Agent 驱动）

```
Agent 进项目 → 自动读 AGENTS.md
  → "Wiki 从 wiki/quickstart.md 开始"
  → 读取 quickstart.md → 内链导航 → 按需读 Wiki 页面
  → Wiki 足够？ → 直接回答（附锚点 file:line）
  → 不够 → 从锚点取符号 → codewiki_callers/callees/impact/node/search/explore
  → 融合图谱事实 → 回答
```

## 四、开发阶段

| 阶段 | 目标 | 核心交付 | 前置 | 技术焦点 |
| --- | --- | --- | --- | --- |
| **P1** | Tree-sitter → SQLite 完整链路 | 建库脚本 + 图谱（nodes/edges/unresolved_refs）+ 图查询 API | 无 | py-tree-sitter, sqlite3, 两阶段落库, ReferenceResolver 翻译, 图遍历算法 |
| **P2** | MCP Server 暴露图谱查询 + 构建 | 8 个 MCP 工具（init/sync/node/callers/callees/impact/search/explore），CC/Codex 可调；init/sync 只构建图谱无 Wiki 生成 | P1 | FastMCP, @mcp.tool(), stdio transport, explore 预算算法 |
| **P3** | Git 提交驱动的自动增量 | `git diff` 变更检测 + 增量重提取 + 跨文件边复活 + 非祖先全量重建 + auto_sync | P1 | GitPython, 增量编排, 文件级 fail-safe |
| **P4** | LLM 生成 Wiki + AGENTS.md | `wiki/`(quickstart + 6 类文档 + 锚点) + AGENTS.md 追加 + 增量定向重写 | P1 | langgraph, openai SDK, prompt 模板, Send 并行, SqliteSaver, subagent |
| **P5** | 产品胶水层（CLI=MCP 统一入口 + 多客户端安装器 + Wiki 管线串联） | typer CLI 注册 8 工具 + installer/targets/ + init 串联 P1→P4 完整流程 | P2,P3,P4 | typer CLI, 配置注入, 多客户端 MCP 配置生成 |

**P3 和 P4 无硬依赖，可并行开发。P2 需要 P1 图谱准备就绪。P5 需要前面全部就绪。**

### 近期聚焦：P1

P1 是整个项目的地基，交付标准：

- 能解析一个 Java 项目，产出 SQLite 图谱（nodes + edges + unresolved_refs）
- 图查询 API 可通过 Python 调用（`get_callers(symbol)` / `get_callees(symbol)` / `get_impact(symbol)` / `search(query)` / `get_node(symbol)`）
- 覆盖：class / method / field / parameter / import / extends / implements / calls / references
- 对齐 codegraph 的 node ID（sha256）和两阶段落库逻辑
- 不做 MCP、不做增量、不做 Wiki

## 五、技术约定

| 约定项 | 规则 |
| --- | --- |
| 代码风格 | ruff（lint + format），CI 自动检查 |
| 类型标注 | 所有公共函数 + 数据模型用 mypy 严格模式 |
| 日志 | logging → FileHandler。MCP stdio 模式 stdout 绝不可输出 |
| 异步 | async/await 贯穿 I/O 密集路径（LLM 调用、文件读写）。图查询（SQLite）可同步 |
| 配置 | LLM API key → `.env`（python-dotenv）；其余 → `.codewiki/config.json` |
| 测试 | pytest，P1 至少覆盖节点 ID 生成、两阶段落库主流程、图遍历三个核心路径 |
| 参考对齐 | 所有图谱逻辑先翻 `CodeGraph参考/` 再写；所有 Wiki 逻辑先看 openwiki（AGENTS.md → quickstart.md 模式） |

## 六、环境搭建

```bash
# 1. 克隆项目
git clone <codewiki-repo>
cd codewiki

# 2. 创建虚拟环境
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate

# 3. 安装依赖
uv pip install -e ".[dev]"

# 4. 配置 LLM API key
echo "OPENAI_API_KEY=sk-xxx" > .env

# 5. 跑测试
pytest

# 6. 试跑 P1 建库
python -m codewiki.cli init /path/to/some-java-project
```
