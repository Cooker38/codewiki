## 关键设计

### M1 设计
- `git diff --name-status C_old C_new` 解析为标准结果 [(status, filePath)]
- 非祖先检测：`git merge-base --is-ancestor C_old C_new`，exit code 0=祖先
- commit 指针：读写 `project_metadata` 表 key=`last_indexed_commit`

### M2 设计
- A/M 文件：调用 P1 的 `extract_from_source` + `store_extraction_result`（已含跨文件边复活）
- D 文件：`store.delete_file(file_path)`（级联删节点+边+unresolved_refs）
- R 文件：删旧 + 加新
- 不变文件：跳过

### M3 设计
- 变更文件重提取后 → 定向重跑 ReferenceResolver（只解析 from_node_id 在变更文件内或 name_tail 被新增符号命中的 failed refs）
- 变更文件的节点 → 重跑 CallbackSynthesizer
- 最后更新 `last_indexed_commit` → 同一事务 COMMIT

### M4 设计
- `threading.Lock` 全局写锁
- sync 结束时 `acquire` → 成功执行 → `release`
- 查询工具调用时 `acquire(blocking=False)` → 失败返回"维护中" → 成功则 `release` 后执行查询

### M5 设计
- `threading.Timer` 或 `asyncio` loop，每 10min 跑一次
- 读取 `.codewiki/config.json` 的 `auto_sync` 字段
- 轮询 `git rev-parse <branch>` 比对 `last_indexed_commit`
