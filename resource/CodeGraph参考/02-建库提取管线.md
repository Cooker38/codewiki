# CodeGraph 实现参考（02 · 建库提取管线）

> 主流程在 `src/extraction/index.ts`（`ExtractionOrchestrator`），并行解析在 `src/extraction/parse-pool.ts`，单语言提取器契约见 `src/extraction/languages/typescript.ts`。

## 1. indexAll 主流程（`ExtractionOrchestrator.indexAll`，`index.ts:1488`）

阶段顺序（确定性、可中断）：

1. **initGrammars()** — 加载 tree-sitter WASM grammar。
2. **scan（扫描）** — `scanDirectoryAsync(rootDir, …)`，产出全部源文件列表（`index.ts:1527`）。
3. **framework 检测** — `ensureDetectedFrameworks(files)` 一次性检测（每 run 重置，故中途加 `requirements.txt` 也能被识别）（:1542-1545）。
4. **解析语言判定** — `detectLanguage` 对每文件判定语言；`.h` 默认 `c` 但会额外加载 `cpp` grammar（:1575-1579）。
5. **建解析池** — `ParseWorkerPool`（见 §2）；无 compiled worker 时退回主线程同步解析（:1584-1610）。
6. **有界滚动窗口 + 按序提交**（见 §3）。
7. **解析完成后** 调 `ReferenceResolver` 绑定跨文件边（由编排层在 indexAll 之后触发，解析阶段只落 `unresolved_refs`）。

进度事件：`onProgress({phase, current, total})`，phase 为 `scanning` / `parsing`（:1517-1534, :1567-1571）。

## 2. ParseWorkerPool 多线程解析（`src/extraction/parse-pool.ts:172`）

把 CPU 密集的 tree-sitter 解析摊到 N 个 worker 线程（SQLite 写留在主线程，非线程安全）：

- **池大小**：`resolveParsePoolSize`（:112）— 显式 `CODEGRAPH_PARSE_WORKERS`；`0/1`→1（旧单 worker 回滚路径）；未设→`clamp(cores-1, 1, 8)`；硬上限 `MAX_PARSE_POOL_SIZE=16`（:59）。
- **worker 回收**：每 worker 解析 `recycleInterval=250` 次后销毁重建，回收 WASM 线性内存（只增不减）（:61）。
- **超时**：基础 `PARSE_TIMEOUT_MS=10s`，按文件大小 +10s/100KB（:63, `dispatch` 处 :332）。
- **硬杀倍率** `HARD_KILL_MULTIPLIER=3`（:75）：基础 timer 触发只标记 late，**不立刻杀**——因为主线程同步 store 卡顿时 timer 会先于已完成的 `parse-result` 触发（#1231），造成误杀丢文件；只有整窗口无结果才真杀（:354-377）。
- **冷启动限流** `MAX_CONCURRENT_SPAWN=2`（:82）：避免同时冷启全部 worker 抢占 CPU。
- **崩溃预算** `CRASH_BUDGET=100`（:89）：超过则停止重建、把 outstanding 工作 fail，避免无限重启。
- **拒绝而非重试**：worker 崩溃/超时的 parse **reject**（消息含 "timed out"），由编排层做更聪明的两阶段重试（新 worker，再退化为去注释重解析）（:19-22）。
- **grammar 内存化**：解析池启动时把每个 grammar 的 WASM 字节读一次（`readGrammarWasmBytes`），分发给每个 worker 的 `load-grammars`，避免 spawn/重生在慢盘上重复读盘放大 I/O 争用（#1231）（:161-169）。

`requestParse`（:227）返回 `Promise<ExtractionResult>`，完成/拒绝都经 `settle`（:409）。

## 3. 有界滚动窗口 + 按序提交（#1015，确定性关键）

`index.ts:1624-1713`：

- 读取并行、解析跨池并发、**SQLite 存储留在主线程**。
- **关键不变量**：结果按**文件顺序（file order）**提交，而非按解析完成顺序。因为解析阶段用「同插入顺序」来消歧同名候选（谁先插入谁优先），稳定提交顺序让图谱**字节级确定**，不随解析时序漂移。
- `completed` 缓冲最多 ~`windowSize`（= `max(4, pool.size*2)`）个乱序结果，内存有界（:1634-1639）。
- `flushOrdered`（:1715）：把 store 串行化到 promise 链上（store 变 async 后必须，保证单写者 + 文件序）。

## 4. storeExtractionResult（落到 DB，`index.ts:2154`）

步骤：

1. `STORE_CHUNK=2000`，分块插 + 每批 `await onYield?.()`（:2168, 防卡死看门狗）。
2. `contentHash` 比对：未变则直接 return（:2169-2175）。
3. **快照跨文件入边**：删文件前 `getCrossFileIncomingEdgesWithTarget(filePath)`（#899，详见 01 §5）。
4. `deleteFile(filePath)`（级联删 edges + unresolved_refs）。
5. 过滤缺必填字段的节点（`validNodes`）（:2205）。
6. `insertNodes(validNodes)` 分块（:2208）。
7. 过滤「两端都真实插入」的边 `validEdges` 后 `insertEdges` 分块（:2213-2223）。
8. **重插跨文件入边**并按 `(filePath,kind,name)` 重解析目标新 id；找不到则复活为 unresolved_ref（:2243-2265）。
9. 批量插 `unresolved_refs`（denormalize `filePath`/`language`）（:2267-2281）。
10. `upsertFile(fileRecord)`（:2284-2294，文件记录最后落，崩溃可重索引）。

## 5. 单语言提取器契约（以 TypeScript 为例，`languages/typescript.ts`）

`typescriptExtractor: LanguageExtractor`：

- **类型集合**：`functionTypes` / `classTypes` / `methodTypes` / `interfaceTypes` / `enumTypes` / `typeAliasTypes` / `importTypes` / `callTypes` / `variableTypes`（:42-53）。
- **`classifyMethodNode`**（:16-39，`classifyTsClassMember`）：`public_field_definition`/`field_definition` 只有值为箭头函数/函数表达式/HOF 包装时才算 method，否则 property——避免把字段误当方法（#808）。
- **`resolveBody`**（:56-84）：处理 class field 箭头函数嵌套、HOF 包装（如 `field = withBatchedUpdates((e)=>{…})`），正确取到 statement_block。
- **`getSignature`**（:87-96）：取 `parameters` + `return_type`。
- **`getVisibility`**（:97-108）：扫 `accessibility_modifier` 子节点。
- **`isExported`**（:109-120）：向上遍历 parent 链找 `export_statement`——能处理深嵌套（箭头函数在 variable 里 3 层）。
- **`isAsync`/`isStatic`/`isConst`**：扫子节点关键字（:121-145）。
- **`extractImport`**（:146-155）：取 `import_statement` 的 source + 整条语句。

其他语言（java/python/go/rust/c#/… 共 40+）实现同一 `LanguageExtractor` 接口，框架特定提取器（route 节点、middleware）在 tree-sitter 主 pass 后由 `frameworkNames` 驱动（`index.ts:1537-1545`）。

## 6. 扫描过滤规则

- `MAX_FILE_SIZE = 1MB`（`index.ts:129`）：超大的生成/压缩/第三方文件会撑爆 WASM 堆与回收预算，1MB 覆盖几乎全部手写源码。
- `DEFAULT_IGNORE_DIRS`（`index.ts:145-`）：从 github/gitignore 整理的忽略目录集合（node_modules/dist/build/vendor/target/.git 类），**不依赖 .gitignore**，但支持显式 `!negation` 纳入。刻意**不**列入 `packages/lib/app/src` 等「可能含一手源码」的通用名，避免误藏真源码（#407）。
- `isFileLevelOnlyLanguage`：yaml/twig/properties 等无符号但有文件级记录，store 时算 `filesIndexed`（:1678-1687）。

## 7. 增量同步 sync（基于文件系统，非 git，`index.ts:2305`）

- **变更检测来源是「文件系统 vs 已索引状态」，永远不是 git**（:2300-2304, :2322-2330）。
- 流程：枚举当前源码文件 → 与 DB 逐文件 reconcile：
  - 廉价 `(size, mtime)` stat 预筛跳过未变文件（**不读不 hash**）；
  - 仅对疑似变更文件读 + `hashContent` 确认真变化（:2405-2419, :2484-2503, :2543-2548）。
- 价值：既适用于非 git 项目，也**能捕获 `git pull`/`checkout`/`merge`/`rebase` 提交后的改动**（这些 `git status` 看不到，因为已是工作区内容）（:2302-2303）。
- 新增/修改/删除分别计数 `filesAdded`/`filesModified`/`filesRemoved`，返回 `SyncResult`。

> 与 watcher 配合：文件改动事件 debounce 后触发 `sync`（见 06 增量同步文档）。
