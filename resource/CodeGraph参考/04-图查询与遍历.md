## 2. 「先标记 visited，再判深度」模式（#1086 / #1089）

callers/callees/impact 都遵守同一修正：

```ts
private getCallersRecursive(nodeId, maxDepth, currentDepth, result, visited) {
  if (visited.has(nodeId)) return;     // ← 先判重
  visited.add(nodeId);                 // ← 先标记
  if (currentDepth >= maxDepth) return;// ← 后判深度
  ...
}
```

- **为什么**：旧代码把「判重 + 判深度」合并，深度触顶时直接 return **没标记 visited**，于是同一父节点经两条边（两调用点 / calls+references）到达的 caller 会被 push 两次，造成重复（#1086）。
- impact 同理（:551-561）：深度边界处的节点必须同时进 `nodes` 与 `visited`，否则两个循环（用不同集合门控）会对其判断不一致，漏掉真实依赖边（#1089）。

## 3. getCallers / getCallees

- **入边类型集合**（`getCallersRecursive:295`）：`['calls','references','imports','instantiates']`。
- **`instantiates` 也算 caller**（#774，:290-294）：`new Foo()` / `Foo(...)` 构造类 = 调用其构造函数。否则 `callers <Class>` 只露出 import 方、漏掉所有构造点，与「改这个类会波及谁」相反。
- **callees 对称**（:350）：函数构造类 → 类是其 callee，callers/callees 互逆，让 `trace` 能跨实例化边界（function→class→其方法）。
- **批量取节点**（N+1 修复，:298-309 / :353-361）：先收集所有 source/target id，`getNodesByIds(ids)` 一次往返，而非每条边一次 `getNodeById`。

## 4. getImpactRadius（改动影响半径，:520）

- 沿**入边**（谁依赖它）反向遍历，收集受影响节点（#536）。
- **容器下钻**（:563-583）：对 class/interface/struct/trait/protocol/module/enum，沿 `contains` 下钻到成员、同深度递归——这样改类的调用方也会出现在影响范围。
- **关键排除 `contains`**（:585-589）：容器「包含」成员但不「依赖」成员，若不排除会向上爬到父 class 再扩张所有兄弟成员，使叶子符号的影响爆炸（#536）。
- 边收集无门控（`edges.push` 无条件，:601）：旧代码门控会丢「经另一路径进来的第二条入边」，虽是同依赖仍漏（#1089）。

## 5. findPath（BFS 最短路径，:617）

- 标准 BFS，队列存 `(nodeId, path)`。
- 每前沿先收集未 visited 的 target id，`getNodesByIds` 批量取（避免每节点 N+1，:654-658）。
- 支持 `edgeKinds` 过滤；空 = 全部边类型。
- 命中 `toId` 即返回完整 path（节点+边序列）；无路径返回 null。

## 6. typeHierarchy（:412）

- `getTypeAncestors`（:438）：沿 `extends`/`implements` 出边向上。
- `getTypeDescendants`（:463）：沿 `extends`/`implements` 入边向下。
- 均用 visited 防环（继承链理论无环，但防御性）。

## 7. provenance 感知（动态边与静态边区分）

- 遍历本身不筛 provenance，但上层（`mcp/tools.ts` 的 `buildFlowFromNamedSymbols`、动态边界识别）通过 `edge.provenance` 判断边是静态真边还是 `heuristic`/`callback`/`framework:*` 合成边。
- 例：`hasHeuristicEdge(id)`（`mcp/tools.ts:1929-1930`）= 该节点的 callers/callees 中任一 `edge.provenance==='heuristic'`，用于在 Flow 里识别动态派发边界。

## 8. 调用约定（给 CodeWiki 复用时的提醒）

1. 所有遍历务必「先 visited 后深度」，否则重复节点。
2. 批量取节点（`getNodesByIds`）而非逐边取，大函数多调用方时差异显著。
3. callers 里 `instantiates` 计入 caller；impact 里务必排除 `contains` 防爆炸。
4. 容器（class 等）做影响分析时要下钻 `contains` 到成员，但反向不要沿 `contains` 上爬。
5. 边类型提升（`calls→instantiates`、`extends→implements`）在解析阶段完成（见 03 §3），遍历拿到的 `kind` 已是最终语义类型。
