# CodeGraph 实现参考（00 · 总览与架构）

> 本系列文档是对 `D:\codegraph`（TypeScript 实现的本地代码智能引擎）的**忠实实现总结**，供 CodeWiki 项目复用「tree-sitter 分析 AST → 存 SQLite → 知识库查询」这套方案时查阅。
> 所有结论均带 `文件:行号` 证据，重事实、不发挥、不提优化（按用户要求，codegraph 本身不在此项目的优化范围内）。

---

## 1. 项目定位

CodeGraph 是一个**本地优先**的代码理解引擎：把任意仓库解析成结构化符号图（存 SQLite），再通过 MCP 工具（`codegraph_explore` 为主）让 Agent 在对话中确定性地检索代码。

- 解析层：tree-sitter（web-tree-sitter WASM）+ 每语言提取器
- 存储层：SQLite（含 FTS5 全文索引）
- 出口层：MCP Server（默认只暴露 `codegraph_explore`）
- 外层能力：增量 watch、Git 钩子、安装器（写入各 IDE/Agent 的 MCP 配置）

## 2. 核心设计原则（最重要，决定了整套方案能不能成立）

### 2.1 「确定的结构」与「需要推断的关系」解耦（两阶段落库）

这是 CodeGraph 设计最精髓的一点，也是 CodeWiki 必须沿用的：

- **AST 阶段只做 100% 确定的事**：建 `nodes`，连文件内 `contains` 层级边，标文件内 `references`（调用点）。
- **跨文件 / 跨模块的关系一律降级为「未解析引用」**（`unresolved_refs` 表，带 `reference_kind`），不急于连真边。
- **下游 `ReferenceResolver` 再跨文件把未解析引用绑定成真边**（`calls` / `imports` / `extends` / `implements` / `instantiates` / `references`）。
- **`type_of` / `returns` / `overrides` 是合成层推断出来的**，根本不是 AST 原始输出。

价值：因为把「能确定的结构」和「要猜的关系」分开，它才能补上 grep 跟不到的动态派发（框架路由、回调、注册表）。CodeWiki 建 SQLite 时务必把 `nodes` / `edges` / `unresolved_references` 三张表分离，不要一步到位只建 `edges`。

### 2.2 节点 ID 是内容寻址的（详见 01 存储层）

`id = sha256("${filePath}:${kind}:${name}:${line}").slice(0,32)`，前缀 `kind:`。这意味着**行号一变，ID 就变**，增量更新时必须用 `(filePath, kind, name)` 重新匹配目标。

### 2.3 确定性 > 速度

- 多线程解析，但**按文件顺序提交** store 结果（不是按解析完成顺序），保证同一名字的多个候选能被解析阶段按插入顺序稳定消歧（#1015）。
- 解析失败走「拒绝 + 编排层两阶段重试」，不做静默重入队。

### 2.4 合成边带 provenance

框架解析、回调合成、启发式推断产生的边都标 `edges.provenance`（如 `heuristic` / `callback` / `framework:xxx`），下游遍历和展示据此区分「静态真边」与「推断边」。

## 3. 三级主链路

```
源码 ──① 建库提取(extraction/)──▶ nodes + contains边 + 文件内references + unresolved_refs
                                         │
                                         ▼
                                    ② 引用解析(resolution/)──▶ calls/imports/extends/... 真边（跨文件绑定）
                                         │
                                         ▼
        SQLite 图谱(nodes/edges/unresolved_refs/files/name_segment_vocab + FTS5)
                                         │
                                         ▼
       ③ 图谱查询(graph/) + 上下文构建(context/) + MCP 出口(mcp/) ──▶ Agent
```

| 阶段 | 入口类 / 文件 | 关键方法 | 产出 |
|---|---|---|---|
| ① 建库提取 | `ExtractionOrchestrator`（`src/extraction/index.ts:1400`） | `indexAll`(:1488) / `sync`(:2305) / `storeExtractionResult`(:2154) | nodes / edges / unresolved_refs / files |
| ① 并行解析 | `ParseWorkerPool`（`src/extraction/parse-pool.ts:172`） | `requestParse`(:227) | 各文件 ExtractionResult |
| ② 引用解析 | `ReferenceResolver`（`src/resolution/index.ts:203`） | `resolveAll`(:608) / `resolveOne`(:765) / `createEdges`(:947) | 真边 + 残留 unresolved |
| ③ 图遍历 | `GraphTraverser`（`src/graph/traversal.ts`） | `getCallers`/`getCallees`/`getImpactRadius`/`findPath` | Subgraph |
| ③ 上下文 | `ContextBuilder`（`src/context/index.ts:187`） | `findRelevantContext`(:432) / `buildContext`(:216) | TaskContext |
| ③ MCP 出口 | `ToolHandler`（`src/mcp/tools.ts:812`） | `execute`(:1354) / `handleExplore`(:2492) | MCP 工具结果 |
| 增量 | `FileWatcher`（`src/sync/watcher.ts`） + `sync` | `start` / debounce | 自动 re-index |

## 5. 复用 CodeGraph 方案时，CodeWiki 必须保留的「不变式」

1. 三表分离：`nodes` / `edges` / `unresolved_refs`。
2. 节点 ID 内容寻址（`filePath:kind:name:line`），增量更新用 `(filePath,kind,name)` 重匹配。
3. 跨文件边在 re-index 时会被 `ON DELETE CASCADE` 误删——必须像 `storeExtractionResult` 那样先快照「跨文件入边」再重绑定（#899）。
4. 图遍历必须「在深度检查前先标记 visited」，否则会重复节点（#1086/#1089）。
5. 合成边必须带 `provenance`，确定性问答时与静态边区分。
6. 增量同步基于「文件系统 (size,mtime) 预筛 + content_hash」，不依赖 git（更易在非 git 项目与 `git pull` 后生效）。
